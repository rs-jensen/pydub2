# Differences from pydub 0.25.1

- ffmpeg `parameters` are placed before the output file, so they take effect.
- Files that fall back to ffmpeg get the same sample width as in pydub (ffprobe, or the `ffmpeg -i` output when ffprobe is missing). Data on a pipe goes through ffmpeg's `cache:` protocol like pydub does, so mp4 with the moov atom at the end works.
- Reading and exporting wav, flac, ogg and opus, and reading mp3, need no ffmpeg. With a missing converter `from_mp3` works instead of raising `OSError`.
- mp3 decodes to the same length as ffmpeg, but a few samples in 1000 are off by 1 LSB (up to 1.5 in 100 against an x86 ffmpeg), because minimp3 does its float synthesis a little differently from ffmpeg's mp3float.
- ogg vorbis has the same length as ffmpeg, samples differ by under 1024 at 32 bit scale (float rounding in a different decoder).
- opus goes through libopus, ffmpeg uses its own opus decoder. The length is the same but samples can differ a lot, up to about a quarter of full scale at low bitrates.
- Loading part of a wav, flac, mp3 or opus file with `start_second` or `duration` seeks in the file instead of running ffmpeg. You get the same frames as pydub (ffmpeg's `-ss`/`-t` rounding, then pydub's slicing), with the same small sample differences as a full load of that format. Part of an ogg vorbis file goes through ffmpeg when it is there, because ffmpeg cuts by packet times that drift from the sample count near the start of some files. Without ffmpeg it is cut at the exact sample, which can be a few hundred samples from pydub. `stream` always cuts at the exact sample.
- A file path is decoded straight from disk, so loading takes about the size of the decoded audio in memory, and wav files over 4 GB (RF64, or a data size of 0xFFFFFFFF from a pipe) work. pydub refuses wav over 4 GB.
- New: `AudioSegment.stream(path, chunk_ms=10000, start_second=None, duration=None)` yields the file in pieces with constant memory. Joined they are the same as `from_file` with the same arguments, except for `start_second` or `duration` on an ogg vorbis file when ffmpeg is installed (see above, `from_file` then uses ffmpeg and `stream` cuts at the exact sample). Only for wav, flac, mp3, ogg and opus.
- `export` of wav and flac with `codec` pcm_s16le, pcm_s24le or pcm_s32le (flac: none or flac) and `parameters` made of `-sample_fmt s16`/`s32`, `-ar` and `-ac` with the current rate and channels is written without ffmpeg, with the same samples. This covers what audio-separator passes for 16, 24 and 32 bit output. Flac with `-sample_fmt s32` is 24 bit like ffmpeg. Anything else (a new rate, a new channel count) still goes to ffmpeg. 24 bit wav gets a plain PCM header where ffmpeg writes WAVE_FORMAT_EXTENSIBLE and a LIST chunk.
- mp3 written by `pydub2_mp3` always starts with an Info frame carrying the encoder delay and padding, also at low constant bitrates where lame has no room for its own and ffmpeg uses a bigger frame, so the file reads back at the length it was written with. The crc fields of that frame are left 0 when lame did not write it.
- Exported ogg, opus and flac files never match ffmpeg byte for byte, but use its settings: opus is unconstrained vbr at 64k per stream plus 32k per coupled pair (96k stereo), vorbis is q3 or, with a bitrate, ABR without slow rate management, flac is level 5 with ffmpeg's block size. Sizes are within a few percent (opus at 16 kHz within 7%, flac is about 8 kB smaller because we write no padding block).
- flac export writes 8 bit audio as 16 bit and 32 bit audio as 24 bit (the low byte is dropped), like ffmpeg, so a file read back has `sample_width` 2 and 4.
- opus: the OpusHead input rate is the real rate where ffmpeg writes the rate it resampled to (48000 for 44100), and the tags name libopusenc where ffmpeg's say Lavf and Lavc. vorbis tags name libVorbis. A vorbis file has more, smaller ogg pages than ffmpeg's. The last granule is the input length, ffmpeg's own decoder can read vorbis a few ms too long.
- `utils.mediainfo` and `mediainfo_json` work without ffprobe for wav, flac, ogg, opus and mp3 (the keys ffprobe gives for the stream and format, as strings). `duration` is the decoded length, ffprobe's can be a bit longer for mp3 and opus. Other files use `ffmpeg -i` (the one from `AudioSegment.converter`) and only get `index`, `codec_type`, `codec_name` and the sample size keys, with strings as values in `mediainfo`.
- `pydub2.logging_utils`, `silence.db_to_float` and the other module level names of pydub exist. `pyaudioop` and the `audioop` name in the modules are not there, the C++ core does that work.
- `detect_silence` and what is built on it return `[]` for audio shorter than `min_silence_len` before looking at `seek_step`, like pydub. A `seek_step` of 0 raises `ValueError` and a float raises `TypeError`, as the `range` call in pydub does. Negative steps and a negative `min_silence_len` follow pydub's own loop.
- No warning at import when ffmpeg is missing.
- `AudioSegment` accepts `bytearray` and `memoryview` as data.
- New: `detect_speech` and `split_on_speech` in `pydub2.silence`.
- `export` takes the format from the extension of the path when `format` is left out (mp3 when the extension is unknown or the target is a file object). `format="pcm"` is the same as `"raw"`, `"m4a"` and `"aac"` work, `bitrate` can be an int and `cover` a `pathlib.Path`.
- Exporting more than 4 GiB as wav raises `CouldntEncodeError` (pydub raises `struct.error`).
- `stereo_to_ms` and `ms_to_stereo` in `pydub2.utils` work (they raise `NameError` in pydub).
- `speedup` is much faster on long audio, with the same output. `speedup` with a `chunk_size` that leaves no room to crossfade (`chunk_size=1`) raises `ZeroDivisionError` at once, like pydub does when it fades the empty first chunk.
- New: `from_mono_audiosegments(..., fill_up=True)` pads shorter segments with silence, `split_on_silence` and `split_on_speech` take `return_ranges=True` and return `(chunk, (start, end))` pairs, `AudioSegment.from_numpy(array, frame_rate)` and `to_numpy()`.
- Things that hang or crash in pydub work: `overlay(empty, loop=True)`, `append` with a crossfade under 1 ms, `low_pass_filter` and `high_pass_filter` on empty audio, `mediainfo` of a file object, files whose name starts with `-`, `format="wma"`, `eq` and the other `scipy_effects` channel modes.
- `export` of wav with `tags` and a `codec` or `parameters` goes through ffmpeg so the tags are written, like pydub.
- `export` of flac, ogg and opus with `tags` writes the Vorbis comments without ffmpeg, with the keys, case, order and values ffmpeg gives them (`album_artist`, `track`, `disc` and `comment` are written as ALBUMARTIST, TRACKNUMBER, DISCNUMBER and DESCRIPTION, keys match without case and the last one wins, an empty value or key drops the entry, `a=b` as a key splits at the first `=`). The `encoder` tag says `pydub2` where ffmpeg's says Lavf or Lavc, and a flac comment block over 16 MiB raises `CouldntEncodeError` where ffmpeg fails earlier on the command line length. `cover` and mp3 are unchanged.
- `mediainfo` and `mediainfo_json` without ffprobe return the tags of wav (LIST INFO), flac, ogg and opus files like ffprobe does (flac and wav at format level, ogg and opus at stream level, doubled keys joined with `;`). mp3 tags still need ffprobe. Invalid utf-8 is replaced per byte in a slightly different way, and `CHAPTER001` style keys and cover pictures are shown as tags where ffprobe makes chapters and streams of them.
- `+=` and `sum()` of many segments are linear, `compress_dynamic_range`, `low_pass_filter` and `high_pass_filter` are several times faster, all with the same bytes. A 24 bit `AudioSegment` is widened without a Python loop.
- ffmpeg is started without a console window on Windows. Output of ffprobe and ffmpeg that is not utf-8 is decoded with errors ignored.
- `strip_silence` and `append` with a crossfade that covers no frame (a few Hz, or under 1 ms) return the audio where pydub raises `ZeroDivisionError` in `fade`. A fade over zero frames does nothing here.
- `rms` of 32 bit audio is summed without fused multiply-add, like audioop on x86. audioop on arm64 (macOS, Linux aarch64) fuses the squares, so a few `rms` values are 1 higher or lower there, `dBFS` changes by about 1e-8 dB and `compress_dynamic_range` can differ by 1 in one 32 bit sample.
- Where pydub raises `audioop.error` or `wave.Error` (`set_sample_width(5)`, `set_frame_rate(0)`, a rate of 0 or below in an export, `get_dc_offset` on 3 channels) pydub2 raises `ValueError`. `remove_dc_offset` with an offset that does not fit the sample width raises `ValueError` where pydub raises `OverflowError`. A negative width, channel count or rate goes the same way (`set_sample_width(-1)`, `set_frame_rate(-5)`, a wav export with width -1 are `ValueError`; `set_channels(0)` is `ValueError` in both). On a new `AudioSegment` a width, channel count or rate of 0 or below raises the same class as pydub (`ZeroDivisionError`, or `ValueError` from `len`).
- A file that wav, flac, mp3, ogg or opus reading cannot decode (damaged or chained vorbis) goes to ffmpeg, and raises `CouldntDecodeError` when ffmpeg is missing. `FileNotFoundError` is only for formats pydub2 cannot read itself.
- Chained opus (several opus streams one after the other) decodes without ffmpeg. libopus starts each link fresh where ffmpeg's decoder carries its state across, so a few samples after each join can differ. A chain whose links have another channel count needs ffmpeg. With ffmpeg installed `from_file` still sends a chained file to ffmpeg, `stream` does not.
- `export` of a 32 bit segment to flac writes 24 bit flac, like ffmpeg. A wav export with a float `frame_rate` rounds it like the `wave` module. A float `frame_rate` (`silent(frame_rate=3.5)`, `44100.0`) works everywhere, `detect_silence` and what is built on it do the millisecond math with the float like pydub.
- Damaged files can have another length than with ffmpeg, a few ms of difference where the damage is. mp3 keeps and drops frames around junk like ffmpeg, mixes a stream that switches between mono and stereo like ffmpeg and decodes a last frame cut short up to the cut. What still decodes differently: mp3PRO, a last frame cut inside its first 36 bytes, frames whose granules claim more bits than the frame has, a short block followed by a normal one (after a dropped frame), and a seek into such a damaged stream, which can differ from the full read for a frame or two after the seek point.
- mp3 in free format, and an mp3 whose sample rate changes inside the file, go to ffmpeg. ffmpeg cannot read free format either, so such a file raises `CouldntDecodeError` with or without ffmpeg, like pydub. Earlier versions of pydub2 decoded free format themselves. An mp3 with a single audio frame raises like pydub too.
- With `pydub2_mp3` and `tags`, the id3 tag is version 2.3 when `id3v2_version="3"` is asked for or ffmpeg is missing, otherwise ffmpeg writes the default 2.4.
- ffmpeg, ffprobe and ffplay are looked up on `PATH`, never in the current directory, and an ffmpeg next to avconv wins over avconv. ffprobe and ffplay are also looked for in the folder of `AudioSegment.converter` when it has one and `PATH` has none. Every call that starts ffmpeg, ffprobe or ffplay uses these, so a private ffmpeg set as `converter` (absolute, relative or with spaces in the path) is enough for reading, `mediainfo` and export, where pydub's ffprobe call fails with `FileNotFoundError`. A monkeypatched `get_prober_name` is used for `mediainfo` and `mediainfo_json`. The functions `get_encoder_name`, `get_prober_name` and `get_player_name` return the full path they found, and `get_prober_name` gives no warning when it finds nothing. `AudioSegment.ffmpeg` and `.ffprobe` are not read, as in pydub.
- Files go to ffmpeg with a `file:` prefix and `-protocol_whitelist`, so a name like `concat:a.wav` is a file name and not a protocol. A URL passed as the file name (`from_file("http://...")`) is not fetched, pydub hands it to ffmpeg and pydub2 looks for a file with that name. A file that starts like an ffconcat script, an HLS playlist or a DASH manifest raises `CouldntDecodeError`. ffmpeg and ffprobe are also given the list of demuxers they may use (`-format_whitelist`), taken from `ffmpeg -demuxers` without hls, dash, concat, imf, sdp, rtsp, rtp and lavfi, so a playlist that is hidden behind a comment or blank lines cannot make them open other files. Asking for one of those with `format=` fails too.
- `pydub2.max_duration` and `pydub2.ffmpeg_timeout` are new, both off by default.
- `mul` (`apply_gain`, fades) with a nan factor, or an infinite factor on a zero sample, raises `ValueError`. The result is undefined in audioop. `fade` with a duration far past the end of the audio and `overlay(loop=True)` give the same bytes as pydub, only faster. Sample widths other than 8, 16, 24 and 32 bit that ffprobe reports for a file are read as 16 bit.
- opusfile 0.12 is patched at build time for CVE-2022-47021 (a null pointer when an allocation fails), the fix is the upstream commit 0a4cd796 and no release has it yet. It also has the fix from opusfile master for a leak on a failed open.

## Files pydub reads wrongly

pydub2 decodes these properly and does not copy pydub.

- WAVE_FORMAT_EXTENSIBLE wav (ffmpeg writes it for more than 2 channels) with a-law, mu-law or float samples: pydub reads the bytes as integer pcm and gives noise.
- flac at 24 bit and 192 kHz with 6 or 8 channels: pydub gives 0 frames.
- wav with 12 bit samples in 16 bit: pydub gives a sample width of 1 and twice the frames.
- WAVE_FORMAT_EXTENSIBLE wav with 24 valid bits in 32 bit samples, from a file object: ffmpeg takes it for 24 bit float and pydub gives noise.

## pydub quirks kept on purpose

These give a result in pydub without an error, so pydub2 gives the same result.

- `AudioSegment.silent()` has the frame count pydub computes, `seg[-1]` is the last millisecond, `speedup(playback_speed=1.0)` shortens the audio.
- `set_frame_rate` resamples without a low pass filter, so high frequencies alias.
- Downmixing more than 2 channels to mono can overflow like in pydub.
- `compress_dynamic_range` releases as slowly as pydub does, a quiet part after a loud one stays attenuated for a while.
- Exporting wav without `codec` or `parameters` ignores `tags`, and tags of a loaded file are not kept when it is exported again. Read them with `mediainfo(path)["TAG"]` (needs ffprobe for mp3).
- 24 bit audio is widened to 32 bit on load, `sample_width` is 4 afterwards. `export(format="wav", codec="pcm_s24le")` writes it as 24 bit.

In the copy of pydub's own test suite (`tests/pydub_suite`) these tests are skipped for the reasons above:
`test_192khz_audio`, `test_opening_mp3_file_fails` and the three `test_partial_load_*_mp3_audio_segment` tests.
